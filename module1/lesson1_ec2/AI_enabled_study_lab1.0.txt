### Topic 1: Databases

Databases are systems that store, organize, and retrieve information so applications can use it efficiently. One of the most important distinctions I have learned is the difference between relational databases, which use SQL and connected tables, and non-relational databases, which can use key-value, document, and graph structures. In my AWS studies, I learned that Amazon RDS is useful when an application needs structured records and relationships, such as a university system connecting students, professors, courses, and grades. Amazon DynamoDB is better suited to applications requiring fast access to data through known access patterns, while Amazon Neptune is useful for analyzing relationships and Amazon Redshift supports large-scale analytical queries. Choosing a database therefore depends on the application's requirements for data consistency, relationships, flexibility, performance, and scalability. PostgreSQL is an established open-source relational database that supports SQL, complex queries, transactions, and extensions, although it may require careful indexing, tuning, and scaling for demanding workloads. From my perspective, the most important lesson is that no database is automatically the best choice: engineers must understand the problem before selecting the technology.

### Topic 2: COBOL

COBOL, which stands for Common Business-Oriented Language, is a programming language developed for processing business and financial information. According to the history of COBOL, its development began in 1959 through the Conference on Data Systems Languages (CODASYL), with support from the United States Department of Defense and contributions influenced by Grace Hopper's earlier programming work. Although COBOL is an older language, it remains important because banks, insurance companies, and government agencies still depend on systems that process financial transactions and maintain essential records. During my SEIR Foundations banking lab, I gained practical experience using COBOL programs to look up accounts, post payments, and interpret return codes that distinguish successful transactions from errors or business rejections. I learned that replacing COBOL involves more than translating old code into a newer language because organizations must preserve business rules, transaction accuracy, data integrity, and connections to other systems. Although COBOL programmers are often described as an aging workforce, I would need reliable workforce data before stating a specific average age. Similarly, estimates of how many systems use COBOL or their total financial value should be attributed to a dated study rather than presented as established facts. My main takeaway is that understanding COBOL remains valuable for cloud engineers because modern APIs and cloud services often need to communicate with legacy financial systems.

### Topic 3: SWIFT

SWIFT stands for the Society for Worldwide Interbank Financial Telecommunication and is a secure financial messaging network used by banks and other financial institutions to communicate payment instructions across international borders. It was established in 1973 by 239 banks from 15 countries to replace slower, less standardized methods of financial communication (Swift, 2026). I learned that SWIFT does not ordinarily transfer the money itself; instead, it provides standardized messages that financial institutions use to coordinate transactions. Alternatives include other financial messaging networks, domestic payment infrastructures, and newer cross-border payment arrangements, although replacing SWIFT is difficult because so many institutions depend on its established standards, security, and international connectivity. During my SEIR Foundations lab, I used a SWIFT traffic generator to simulate payment requests and observed how transactions could be posted successfully or rejected according to business rules. Another important development is the adoption of ISO 20022, a financial messaging standard that supports richer and more structured payment information. Older SWIFT payment message types, including MT103 for customer credit transfers and MT202 for financial-institution transfers, correspond to ISO 20022 messages pacs.008 and pacs.009, respectively. According to Swift's 2025 migration guidance, the coexistence period for traditional MT and ISO 20022 cross-border payment instructions ended on November 22, 2025, although limited contingency translation arrangements remained available. My main takeaway is that cloud engineers working with financial systems must understand both the technical infrastructure supporting transactions and the messaging standards that allow different institutions to communicate reliably.

### Topic 4: APIs

An Application Programming Interface (API) allows different software applications to communicate, exchange information, and request services without needing to understand each other's internal programming. Although APIs existed before the modern internet, REST became an influential approach to designing web APIs after computer scientist Roy Fielding formally described it in 2000 (IBM, 2025). APIs are now widely used in cloud computing, banking, healthcare, education, and artificial intelligence, although there is no single reliable count of all APIs or systems using them. During my SEIR Foundations Balerica Legacy Bank lab, I gained practical experience working with a REST-style API built using Python's FastAPI framework and running through Uvicorn on an AWS EC2 instance. I learned that GET requests are generally used to retrieve information, such as account details or system status, while POST requests submit information for processing, such as payment instructions or questions sent to an API endpoint. I also learned that JSON (JavaScript Object Notation) provides a structured format for exchanging information between applications, making it easier to interpret responses from the banking system. Although REST is widely used, alternatives such as SOAP, GraphQL, and gRPC offer different approaches to application communication. APIs are particularly important to AI adoption because they allow applications to send requests to AI services and integrate generated responses into existing workflows. However, APIs also create security challenges involving authentication, authorization, data exposure, and malicious requests, which makes validating incoming data essential. My main takeaway is that APIs allow modern cloud applications to interact with existing systems without requiring every component to be rewritten.

### Topic 5: Intersection of COBOL, SWIFT, APIs & Databases

The intersection of COBOL, SWIFT, APIs, and databases demonstrates how older technologies and modern cloud computing systems can work together to support critical operations. COBOL continues to process business transactions in some legacy systems, while SWIFT provides standardized financial messages that allow banks to communicate payment instructions. APIs connect these systems to modern applications, and databases store the account information, transaction records, and other data needed to support their operations. During my SEIR Foundations Balerica Legacy Bank lab, I observed how a Python FastAPI application could communicate with COBOL programs, process simulated SWIFT payment traffic, and return transaction results through API endpoints. This experience helped me understand that cloud modernization does not always require replacing an organization's existing technology; it can also involve creating secure interfaces that allow older systems to communicate with newer applications. These principles extend beyond banking into healthcare, education, and government, where institutions depend on reliable access to historical records, financial information, and essential services. According to a 2025 U.S. Government Accountability Office report, federal agencies continue to face challenges modernizing critical legacy systems because of cybersecurity risks, maintenance costs, and shortages of specialized technical expertise. The report identified 11 particularly critical federal legacy systems, demonstrating the continuing importance of modernization planning (U.S. GAO, 2025). My most important takeaway is that cloud engineers must understand how different technologies interact, preserve existing business functions, and modernize systems without disrupting the people and institutions that depend on them.
